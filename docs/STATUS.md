## Em Andamento
- **Fatia 13.6 — Probe HTTP de URL declarada: o "confronto com o mundo" (SPEC-013.6)** — prio: **alta** (ADR-018 aprovado). Estende a 13 com a única fonte que toca a realidade: GET HTTP à URL declarada, confirma liveness e identifica plataforma de **domínio próprio** pelos headers. **Único ponto com superfície SSRF** — as 7 guardas do ADR-018 são critério de aceite: só https; rejeição de IP não-público pós-DNS (loopback, link-local/metadata, RFC1918, CGNAT, ULA v6); **DNS rebinding fechado por pin de IP** (`https.request` + lookup custom, stdlib do Node, zero dep nova — evita o ESM/CJS do Octokit); redirect re-validado (teto 3), sem downgrade; HEAD corpo ≤64KB timeout 5s; zero credencial; só veredito persistido. Sinal `declaredUrl` ganha `mode: string|probe|bloqueada_por_seguranca`; probe falho ≠ inseguro → cai no parse de domínio (decisão do PI). `deploy-probe.ts` (26 testes), `http-probe.spec` (12 testes de segurança), integração (7 testes). 376 testes, builds limpos. **Review de segurança 0 CRITICAL/HIGH** (1 MEDIUM de rate-limit corrigido). **Validado ao vivo:** metadata/loopback/http bloqueados; fingerprint real de netlify/vercel/cloudflare; `mode: probe` no sync do rrb-organize. **Em implementação — aguardando PR + aceite do PI.**

- **Sync SHA-aware — elimina o `noop` falso** (bug documentado, ADR/ARCHITECTURE → Resiliência; entregue junto da Fatia 7): a Git Trees API tem consistência eventual — re-sync imediato após write-back lia a árvore anterior, calculava o mesmo hash e gravava `noop`, afirmando "nada mudou" logo após mudar (o produto mentindo no seu mecanismo central).
